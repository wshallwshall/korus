## Why this page exists at all, which is not obvious

Without `404.html`, Cloudflare Pages serves the home page with status `200` for unknown
addresses. A broken link then looks successful to both readers and automated checks.

This error page lets the host return a real `404` for an unknown address.

On 2026-08-10, a sibling site without `404.html` returned `200` and the home page's bytes for
a nonexistent address. Adding the file restored `404`, which the previous GitHub Pages host supplied by default.

A browser does not normally show the status code. Check it directly:

```
curl -sI "https://claude-multisession.pages.dev/no-such-page-$(date +%s)" | head -1
```

`HTTP/2 404` is the expected result. `HTTP/2 200` means unknown addresses are reporting
success. The random suffix avoids a cached response for a fixed path.

The original build derived its page list from tracked files, so deleting this file also
removed it from the checks. The revision manifest now requires both this page and its archive to render.
